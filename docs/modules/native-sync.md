# Native SyncServer 客户端接入方案

## 职责与协议来源

本模块拥有 PhotoViewer 的原生同步接入实现，不拥有服务端协议。服务端规格、接口、字段所属记录、摘要编码、错误与版本条件的唯一来源是[协议入口](native-sync-protocol.md)链接到的相邻 SyncServer 仓库。链接暂用本地相对路径，正式发布时改为对应版本的仓库网页链接。

客户端知识资产包括：服务端数据到本地媒体的映射、数据库事务、上传范围、任务调度、dirty 与确认基线、已发出操作恢复、成对资源发布、缓存复用和交互。发现 wire 不一致时，修正适配实现；协议变更在服务端仓库提出，不能在此处另写一套规范。

HTTP 传输、请求序列化、响应解码和线上错误分类由服务端仓库的客户端 SDK 提供。`Cargo.toml` 以 GitHub 依赖锁定 `sync-client` 的提交；本地 `native/` 只保留端点/能力校验、SDK 错误到 `SyncError` 的映射、照片领域映射以及租约和发布决策。SDK 需要变更时，先在 SyncServer 仓库合入并推送，再更新这里的锁定提交；不能以本地路径依赖作为发布形态。

## 当前实现与验证边界

自动续批使用纯上行模式：一次同步触发只在首个批次执行下行/发布协调；无失败批次通过原子响应登记 record 身份、版本和资源基线后，直接采用服务端当前水位，后续批次不再重复下行投影。

C1.1–C1.4 已有连接、接收、上行和资源实现。2026-10-15 静态检视发现的九项偏差已在本地修订并通过相关聚焦测试，详见[修订说明](native-sync-integration.md)。当前不将编译通过称为完整运行验收。

构建前提：`sync-client` 是 GitHub 依赖。仓库未公开时，本地需要可用的 git 凭据（libgit2 取不到时设置 `CARGO_NET_GIT_FETCH_WITH_CLI=true`），CI 和 Flatpak 打包需要公开仓库或注入只读凭据。`cargo-sources.json` 已按锁定的提交重新生成；直接运行 `run-flatpak.sh` 仍通过宿主 Cargo 缓存取依赖，离线打包则使用已生成的 git source。

原 WebDAV 引擎已移除。当前仍为未发布的开发阶段，数据库版本始终为 **1**，表结构以 `schema.sql` 为准，不维护开发版本之间的迁移兼容。

C1.5 已接入设置、自动调度、相册选择及逐照片发布；一次触发先完成下行/发布协调再上行，成功批次后只要仍有义务就立即续跑下一批，连续 8 批后让出一次调度再继续，失败批次不触发该续跑。后台自动同步仅由本地变更停止 10 秒后触发；没有定时轮询。启动不主动同步，但会对仍持有脏上行条目或未结算下行资源的任务恢复一次上次遗留的工作；失败也不安排定时重试。显式云删除与不同身份的版本选择保留底层接口，独立管理界面已移除。照片通过现有图库查看和管理；操作见[使用指南](native-sync-usage.md)。相同 `recordId` 的双端修改按各类别的真实修改事件时间自动决定结果，不生成需要手动选择的编辑冲突；时间相同使用来源和事件 ID 稳定排序。路径相同不代表 recordId 相同。此前实机与阶段性验证记录见[实现说明](native-sync-integration.md)。

## 模块边界

| 实现位置 | 客户端职责 |
|---|---|
| `sync/native/protocol.rs` | 端点与能力校验、SDK 连接适配、同源认证策略和错误分类 |
| `sync/native/records.rs` | 校验单张照片的元数据与原图／缩略图引用 |
| `sync/service/receive.rs`、`sync/service/receive/collisions.rs`、`sync/store/receive.rs` | 共享快照、单张未完成字段、元数据直接入库、ingest/applied 的本地事务 |
| `sync/service/coordinator.rs` | 单轮接收、取锁、保活、一次水位检查、分类上行与结果恢复 |
| `sync/store/runtime.rs` | actor 内的配置/轮次/版本校验、已发出操作证据与最终媒体提交 |
| `sync/content.rs`、`sync/native/assets.rs` | 稳定源快照、同源缩略图、流式资源传输与校验 |
| `sync/service/transfer.rs` | 逐照片发布意图、缓存准备、文件回滚与启动恢复 |
| `sync/publication_io.rs` | 本地解码/编辑与短暂发布窗口的读写保护，独立于服务器租约 |
| `sync/store/dirty.rs` | 既有 sync_entries 上的用户变更事实与类别版本 |

## 连接与本地范围

连接地址经过规范化和能力探测后，保存已接受的 namespace、zone、数据库代际和能力。用户名密码登录的会话 Bearer 通过平台凭证服务管理，密码不持久化；旧 API key 关系可在原数据接管后升级。多账户行为见[客户端接入](native-sync-accounts.md)。签名资源地址必须同源，不跟随重定向，不把租约或 Bearer 发给未配置主机。

一个任务绑定一个本地根和一个 zone。当前产品只开放 Sync/Bidirectional；Backup 的不可变历史、目录和恢复交互没有独立验收，不能借用服务端历史保留来宣称支持。多个任务可下行；上行权限来自服务端，不能用本地互斥代替。

上传视图只覆盖用户明确选择的物理相册或 All 范围。离线设备、移出范围与未选择相册不自动生成云端删除；移入或恢复回收站仅为元数据修改，确认文件彻底删除后才记录删除。原生隐藏照片没有本地展示模型时保留冲突，不能公开入库或变成回收站项目。

## 结构化存储与下行预算

所有云图／同步持久化状态使用普通列和关联表，不保存 JSON 文档或序列化 BLOB。账号、接收片段、确认基线、修改事件、摘要、已发出请求、冲突和文件发布恢复的落点见[结构化存储](native-sync-relational.md)。旧文档字段在一个事务中转换并移除；转换失败回滚，保持开发 schema 版本 1。

当前批次上限 100 条记录，以请求开始到该页应用及进度落库不超过 1 秒为目标。版本按索引先查待接收记录，再读已确认字段；同页只比较涉及的本地路径。INFO 页日志分别记录 `http_ms`、`persist_ms`、`apply_ms`、`checkpoint_ms` 和总 `elapsed_ms`。

## 接收与本地进度

远端元数据直接写入 `media_items`，不维护独立的 inbox、云端投影或同步清单。`storage_location` 为 1=local、2=cloud（原图未下载）、3=both（原图已在本地且有云端身份）；`thumbnail_ready` 对本地原图表示缩略图已生成，对纯云端照片表示缩略图已下载并写入缓存。只有 2 且缩略图未就绪的记录暂不展示。

正常轮次只处理水位之后明确收到的记录。跨页尚未配齐的 Master/Asset 保存在结构化 `sync_records` 记录头和 `sync_record_fields` 有类型字段中，关联已有同步 entry，配齐后应用并清除；不重放完整云端历史。首次接收和游标失效保留分页／快照标记。空增量保留既有身份和计数，缺项不推断删除。 已确认身份与当前账号、数据库代际一致时，即使收到与基线完全相同的记录，也先恢复本地照片的两端可用状态；该修复不确认任何新编辑、不结算文件发布。

接收页先将单张未完成字段、照片元数据与 ingest 位置经 DbActor 持久化；资源就绪前也已经有图片数据库行。跨页 atomic 对在本轮结束后才应用，首次快照中配齐的照片可以逐页应用。下载待办和原有发布意图负责文件恢复；不再维护第二份全量照片数据。

资源待办包含未下载、暂存、失败以及尚未完成发布的状态；开放冲突也阻止 applied。每张照片的发布准入只检查自己的两个角色，不能等待整个任务的所有照片同时完成。只有媒体、两角色和发布意图在同一最终事务中结算后，才允许推进 applied。

已确认本地版本可复用稳定资源；元数据独立变化不重新下载原图。相同 recordId 的元数据与内容分别采用最新修改事件。下行同相册同名时先比较大小，同大小才计算 SHA-256；相同内容合一，不同内容将本地文件保留为未占用的 `_x` 名字，云端文件使用原名。接收旧摘要不能清除测量后新产生的 dirty，远端胜出则只结算本次比较覆盖的类别版本。

## 用户变更与上行确认

首个上行批次前完成本地接收与协调；无失败的确认批次可以直接推进水位，后续续批不再重建远端投影。上传确认直接把图片的 cloud ID、版本、资源基线、位置状态和 dirty 结算写在同一事务内；无须复制到另一份云端清单，后续空增量不重置成功计数。

dirty 为互斥状态：0 无变更、1 新增、2 修改、4 彻底删除；内容和元数据通过各自版本／确认计数区分。文件彻底删除后，既有同步记录保留 dirty=4 及云端身份、版本和删除事件，直到云端删除确认成功；重启、重试、扫描和后续远端修改均不得清除它。仅显式切账号或关闭同步开关可以丢弃待删除记录。

用户变更事实保存在既有 `sync_entries` 的 dirty、本地版本和类别事件中，不另建 dirty 文件或镜像队列。收藏、编辑和位置写入与其 dirty 记录同事务。接受配置编辑后使旧轮次失效；打开、草稿、取消和无效输入不停止任务。

每次租约内的上行轮次最多处理 5 张带文件附件的照片和 20 条纯元数据操作，两类额度独立，跨 Delete/Modify/Create 阶段累计。新建照片和内容替换占附件额度；收藏、路径等元数据更新及删除占纯元数据额度。重试未确认操作也占相应额度；只查询并结算已提交结果不占上行额度。超额项目保留 dirty，由既有自动调度继续处理，不作为同步失败。原图与缩略图仍作为一张照片完整提交。首次清单与增量下行每页请求最多 100 条记录，服务端声明更小上限时取更小值。

上行前先完成本地接收与协调。租约持有期间独立保活；取锁后先用已应用水位做一次服务端检查，未追平时释放租约并立即重新调度下一轮，不在锁内补拉。通过服务端门槛后冻结本地数据库视图；不同类别按服务端阶段派发。元数据读取真实本地字段；原文件制作稳定快照，缩略图直接复用本地缓存，再提交照片对；删除保留身份与版本直至确认。

上行按 Large、Medium、Small 顺序查找源路径/mtime 对应的本地缩略图，不检查缓存的源内容摘要，允许原文件与缓存暂时存在版本差异，后续内容变更继续由现有 dirty/版本确认机制处理。缓存不存在时保留 dirty、正常延后，不报告上传失败，也不占附件额度；等待本地缩略图流程生成后，在新的本地变更或显式触发的轮次中重试。原图超过服务端上限时同样在消耗附件额度前延后；后续轮次只做元数据检查，不制作快照、不请求上传、不报告单张失败，文件内容或服务端能力变化后可恢复。上行不解码原文件、不抽取视频帧，也不请求生成缩略图。符合服务端限制的 JPEG/PNG 直接使用原缓存字节；WebP 或超限缓存仅转换/缩小缩略图本身。纯元数据变更和删除不需要缩略图。

单张照片的上行失败原因记录在 `sync_entries.native_upload_error`。新轮次被接受时，仅清空该任务的旧失败原因；失败原因通过 DbActor 按当前配置与轮次回填。已标记失败的照片本轮不再准备、查询回执或上行，其他照片继续；下一轮重新尝试。首次准备/提交、旧操作回执查询/确认及重试使用同一规则。失败不清 dirty、不更新本地版本、不丢弃未知提交证据；成功项目不回滚。租约失效、配置过时、数据库代际变化或无法结算旧配置的已发出操作仍停止本轮。

`sync_tasks` 只记录已经准备发出、结果可能未知的操作。其 UUID、配置与版本捕获、规范化逻辑请求以及资源会话身份持久化；不保存 capability URL 或 leaseToken。下一轮先读取既有结果，再决定是否重发同一个逻辑操作。

成功确认核对已发出操作、完整原子结果、配置、轮次、数据库代际、租约有效期与类别版本。确认创建后登记远端身份；并发新编辑继续 dirty。跳过、失败、失锁和过时响应不清义务；只读 AlreadyCurrent 必须先验证真实远端目标状态。

## 本地发布与恢复

资源校验和缓存准备在阻塞任务或有界异步 I/O 中完成，不占 GTK 请求线程或 SQLite 事务。原图与缩略图都准备好后，持久保存发布意图及捕获版本，保护旧完整文件，再执行同文件系统替换和 actor 最终提交。

普通索引/upsert 不能穿过发布窗口。本地图片读取和编辑共享短暂文件发布保护；网络传输不持有该保护。崩溃后先结算拥有的发布意图，再加载首屏和启动扫描。失败或检测到后来的外部修改时保留旧文件/备份，不静默覆盖。

缩略图使用现有本地 URI、最终 mtime 和 Small/Medium/Large 缓存键，宫格与详情继续走本地加载，不增加网络占位或浏览触发原图下载。下行导入时源字节只解码一次，再缩放/编码成三个档位；缓存写入走临时文件加原子重命名，不做逐文件 fsync（缓存可重建，后台校验会修复缺失），避免每张照片六次同步写入阻塞传输循环。

## 设置页状态刷新

设置页的同步数量、任务列表、账号名称和上传范围摘要统一由后台 worker 读取，再回到 GTK 更新现有控件。页面首次显示时加载一次；之后数量仅由 `SyncStateDirty` 同步进度／生命周期事件触发查询。窗口对连续事件做前缘刷新加 300ms 合并，下载期间不会为每张照片重复读取总库计数。`SyncConfigurationDirty` 只更新任务控制和范围摘要，复用已缓存的数量，不设置周期查询。隐藏期间只记失效，重新显示后补读；同一时间最多一个读取任务，读取期间的事件合并处理，不在 GTK 主线程等待连接池或执行统计 SQL。开关和关闭确认框不依赖这些展示统计完成。

概览按照片检查未完成发布时，必须使用 `sync_publications(entry_id,state)` 索引，避免每张照片扫描全部发布记录。存储测试覆盖 4000 张照片的计数与查询计划，`tests/ux_native_sync_disable.rs` 在连接池被占用时通过真实点击验证确认、取消及页面响应。

## 全局开关确认

全局开关通过 `GtkSwitch::state-set` 接收用户请求。关闭确认仍是草稿：打开或取消确认框时保持开关已启用，不保存设置、不清历史、不重新调度任务。只有接受关闭才保存 Off 并发起既有的持久清理；程序回填开关状态不会再次进入启用或关闭处理。不要在 `notify::active` 中反向修改 `active`，否则通知结束后的回调会把状态回填当成新的启用请求。

`tests/ux_native_sync_disable.rs` 通过真实点击验证关闭确认、取消、确认及之后的设置页导航，同时检查确认前没有重写配置。

## 单一当前账号与切换

客户端同时只同步一个账号；不同账号保存独立任务，可复用本地目录，切换时先结算旧运行再启动新账号，服务器用户身份保存在既有 pinned scope。连接地址相同不表示同一账户；每次实际传输前核对身份与数据库代际，错误会话不推进进度。登录、重新登录、退出及旧关系升级见[多账户接入](native-sync-accounts.md)。服务器协议只由相对链接引入，不在客户端另建版本。
