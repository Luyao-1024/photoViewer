# Native SyncServer 客户端接入方案

## 职责与协议来源

本模块拥有 PhotoViewer 的原生同步接入实现，不拥有服务端协议。服务端规格、接口、字段所属记录、摘要编码、错误与版本条件的唯一来源是[协议入口](native-sync-protocol.md)链接到的相邻 SyncServer 仓库。链接暂用本地相对路径，正式发布时改为对应版本的仓库网页链接。

客户端知识资产包括：服务端数据到本地媒体的映射、数据库事务、上传范围、任务调度、dirty 与确认基线、已发出操作恢复、成对资源发布、缓存复用和交互。发现 wire 不一致时，修正适配实现；协议变更在服务端仓库提出，不能在此处另写一套规范。

## 当前实现与验证边界

自动续批使用纯上行模式：一次同步触发只在首个批次执行下行/发布协调；无失败批次通过原子响应登记 record 身份、版本和资源基线后，直接采用服务端当前水位，后续批次不再重复下行投影。

C1.1–C1.4 已有连接、接收、上行和资源实现。2026-10-15 静态检视发现的九项偏差已在本地修订并通过相关聚焦测试，详见[修订说明](native-sync-integration.md)。当前不将编译通过称为完整运行验收。

原 WebDAV 引擎已移除。当前仍为未发布的开发阶段，数据库版本始终为 **1**，表结构以 `schema.sql` 为准，不维护开发版本之间的迁移兼容。

C1.5 已接入设置、自动调度、相册选择及逐照片发布；一次触发先完成下行/发布协调再上行，成功批次后只要仍有义务就立即续跑下一批，15 秒定时器只是无进展时的回退检查。显式云删除与不同身份的版本选择保留底层接口，独立管理界面已移除。照片通过现有图库查看和管理；操作见[使用指南](native-sync-usage.md)。相同 `recordId` 的双端修改按各类别的真实修改事件时间自动决定结果，不生成需要手动选择的编辑冲突；时间相同使用来源和事件 ID 稳定排序。路径相同不代表 recordId 相同。此前实机与阶段性验证记录见[实现说明](native-sync-integration.md)。

## 模块边界

| 实现位置 | 客户端职责 |
|---|---|
| `sync/native/protocol.rs` | 连接策略、能力探测、同源认证传输和服务端 DTO 适配 |
| `sync/native/records.rs` | 按服务端照片契约构建本地远端投影，保留未知记录 |
| `sync/service/receive.rs`、`sync/service/receive/collisions.rs`、`sync/store/receive.rs` | 共享快照、持久 inbox、完整投影、ingest/applied 的本地事务 |
| `sync/service/coordinator.rs` | 单轮接收、取锁、保活、一次水位检查、分类上行与结果恢复 |
| `sync/store/runtime.rs` | actor 内的配置/轮次/版本校验、已发出操作证据与最终媒体提交 |
| `sync/content.rs`、`sync/native/assets.rs` | 稳定源快照、同源缩略图、流式资源传输与校验 |
| `sync/service/transfer.rs` | 逐照片发布意图、缓存准备、文件回滚与启动恢复 |
| `sync/publication_io.rs` | 本地解码/编辑与短暂发布窗口的读写保护，独立于服务器租约 |
| `sync/store/dirty.rs` | 既有 sync_entries 上的用户变更事实与类别版本 |

## 连接与本地范围

连接地址经过规范化和能力探测后，保存已接受的 namespace、zone、数据库代际和能力。用户名密码登录的会话 Bearer 通过平台凭证服务管理，密码不持久化；旧 API key 关系可在原数据接管后升级。多账户行为见[客户端接入](native-sync-accounts.md)。签名资源地址必须同源，不跟随重定向，不把租约或 Bearer 发给未配置主机。

一个任务绑定一个本地根和一个 zone。当前产品只开放 Sync/Bidirectional；Backup 的不可变历史、目录和恢复交互没有独立验收，不能借用服务端历史保留来宣称支持。多个任务可下行；上行权限来自服务端，不能用本地互斥代替。

上传视图只覆盖用户明确选择的物理相册或 All 范围。离线设备、移出范围、本地独立删除与未选择相册都不自动生成云端删除。原生隐藏照片没有本地展示模型时保留冲突，不能公开入库或变成回收站项目。

## 接收与本地进度

元数据页、接收位置和投影通过现有 DbActor 持久化。跨类型首次清单完成后，才协调完整照片图。网络上读取到新位置不等于本地已完成。

资源待办包含未下载、暂存、失败以及尚未完成发布的状态；开放冲突也阻止 applied。每张照片的发布准入只检查自己的两个角色，不能等待整个任务的所有照片同时完成。只有媒体、两角色和发布意图在同一最终事务中结算后，才允许推进 applied。

已确认本地版本可复用稳定资源；元数据独立变化不重新下载原图。相同 recordId 的元数据与内容分别采用最新修改事件。下行同相册同名时先比较大小，同大小才计算 SHA-256；相同内容合一，不同内容将本地文件保留为未占用的 `_x` 名字，云端文件使用原名。接收旧摘要不能清除测量后新产生的 dirty，远端胜出则只结算本次比较覆盖的类别版本。

## 用户变更与上行确认

首个上行批次前完成本地接收与协调；无失败的确认批次可以直接推进水位，后续续批不再重建远端投影。

用户变更事实保存在既有 `sync_entries` 的 dirty、本地版本和类别事件中，不另建 dirty 文件或镜像队列。收藏、编辑和位置写入与其 dirty 记录同事务。接受配置编辑后使旧轮次失效；打开、草稿、取消和无效输入不停止任务。

每次租约内的上行轮次最多处理 5 张带文件附件的照片和 20 条纯元数据操作，两类额度独立，跨 Delete/Modify/Create 阶段累计。新建照片和内容替换占附件额度；收藏、路径等元数据更新及删除占纯元数据额度。重试未确认操作也占相应额度；只查询并结算已提交结果不占上行额度。超额项目保留 dirty，由既有自动调度继续处理，不作为同步失败。原图与缩略图仍作为一张照片完整提交。首次清单与增量下行每页请求最多 100 条记录，服务端声明更小上限时取更小值。

上行前先完成本地接收与协调。租约持有期间独立保活；取锁后先用已应用水位做一次服务端检查，未追平时释放租约并立即重新调度下一轮，不在锁内补拉。通过服务端门槛后冻结本地数据库视图；不同类别按服务端阶段派发。元数据读取真实本地字段；原文件制作稳定快照，缩略图直接复用本地缓存，再提交照片对；删除保留身份与版本直至确认。

上行按 Large、Medium、Small 顺序查找源路径/mtime 对应的本地缩略图，不检查缓存的源内容摘要，允许原文件与缓存暂时存在版本差异，后续内容变更继续由现有 dirty/版本确认机制处理。缓存不存在时保留 dirty、正常延后，不报告上传失败，也不占附件额度；等待本地缩略图流程生成后由后续自动轮次重试。原图超过服务端上限时同样在消耗附件额度前延后；后续轮次只做元数据检查，不制作快照、不请求上传、不报告单张失败，文件内容或服务端能力变化后可恢复。上行不解码原文件、不抽取视频帧，也不请求生成缩略图。符合服务端限制的 JPEG/PNG 直接使用原缓存字节；WebP 或超限缓存仅转换/缩小缩略图本身。纯元数据变更和删除不需要缩略图。

单张照片的上行失败原因记录在 `sync_entries.native_upload_error`。新轮次被接受时，仅清空该任务的旧失败原因；失败原因通过 DbActor 按当前配置与轮次回填。已标记失败的照片本轮不再准备、查询回执或上行，其他照片继续；下一轮重新尝试。首次准备/提交、旧操作回执查询/确认及重试使用同一规则。失败不清 dirty、不更新本地版本、不丢弃未知提交证据；成功项目不回滚。租约失效、配置过时、数据库代际变化或无法结算旧配置的已发出操作仍停止本轮。

`sync_tasks` 只记录已经准备发出、结果可能未知的操作。其 UUID、配置与版本捕获、规范化逻辑请求以及资源会话身份持久化；不保存 capability URL 或 leaseToken。下一轮先读取既有结果，再决定是否重发同一个逻辑操作。

成功确认核对已发出操作、完整原子结果、配置、轮次、数据库代际、租约有效期与类别版本。确认创建后登记远端身份；并发新编辑继续 dirty。跳过、失败、失锁和过时响应不清义务；只读 AlreadyCurrent 必须先验证真实远端目标状态。

## 本地发布与恢复

资源校验和缓存准备在阻塞任务或有界异步 I/O 中完成，不占 GTK 请求线程或 SQLite 事务。原图与缩略图都准备好后，持久保存发布意图及捕获版本，保护旧完整文件，再执行同文件系统替换和 actor 最终提交。

普通索引/upsert 不能穿过发布窗口。本地图片读取和编辑共享短暂文件发布保护；网络传输不持有该保护。崩溃后先结算拥有的发布意图，再加载首屏和启动扫描。失败或检测到后来的外部修改时保留旧文件/备份，不静默覆盖。

缩略图使用现有本地 URI、最终 mtime 和 Small/Medium/Large 缓存键，宫格与详情继续走本地加载，不增加网络占位或浏览触发原图下载。

## 单一当前账号与切换

客户端同时只同步一个账号；不同账号保存独立任务，可复用本地目录，切换时先结算旧运行再启动新账号，服务器用户身份保存在既有 pinned scope。连接地址相同不表示同一账户；每次实际传输前核对身份与数据库代际，错误会话不推进进度。登录、重新登录、退出及旧关系升级见[多账户接入](native-sync-accounts.md)。服务器协议只由相对链接引入，不在客户端另建版本。
