## 接入实现细节

`service/coordinator.rs` 是轮次入口，`store/runtime.rs` 是同步 DbActor 命令。HTTP 或大文件准备不在数据库事务内等待。确认只清捕获版本匹配的部分，已确认事实和当前用户义务分开保存。未知响应保留原请求身份；签名能力每次从服务端描述刷新，不写入持久请求正文。

`service/transfer.rs` 先校验流式下载，再准备原图、缓存和媒体元数据；文件发布意图包含目标、同目录新文件/备份、配置与本地版本捕获。原图替换失败或最终事务拒绝时恢复旧完整版本。启动时在首屏与扫描之前执行恢复；全局关闭清理前同样先结算意图，避免把备份当作普通临时文件删除。

本地读写保护与服务端租约用途不同：前者仅保护本应用短暂的文件/缓存可见性，后者由服务器授予远端写权限。外部进程不受本地锁控制，因此恢复时仍检查路径所有权和文件变化；发现未知修改就保留备份并报告失败。

本地内容与远端元数据、或本地元数据与远端内容的独立修改按已确认基线协调；同类变更或不明确身份保留冲突。冲突解决交互、显式云删除用户入口、完整 UI 状态和系统性双设备恢复旅程仍属于 C1.5/C1.6，不因本轮代码修订而标为已验收。

## 2026-10-16 开发阶段规则更新

以上 schema 9/10/11 与迁移验证是此前阶段的历史记录。当前未发布版本的数据库编号始终固定为 **1**，不维护开发结构之间的迁移兼容，结构以 `schema.sql` 为准。

相同 recordId 的双端修改改为按独立 metadata/content 事件时间自动决定结果；相同时间按来源和事件 ID 稳定排序。路径相同不启用这条规则；下行的不同身份同名文件按大小/SHA-256 合并或将本地文件保留到空闲的 `_x` 名称。纯本地索引不记录 SHA-256，上传时计算稳定快照摘要。接管身份时，现读与缓存摘要都带 entry ID 和测量时的本地版本，不能确认测量后产生的新编辑。当前契约见[存储方案](native-sync-storage.md#same-record-concurrent-edits)；真实双客户端旅程改为验证两种编辑先后顺序、独立元数据保留及同 recordId 的重命名收敛。
