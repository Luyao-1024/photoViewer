# 原生客户端静态检视修订

日期：2026-10-15。本页记录客户端实现知识，不定义服务端协议；唯一协议来源见[入口索引](native-sync-protocol.md)。静态修订后，用户进一步授权基本相关测试；本轮只执行聚焦验证，不执行全量套件。

## 九项偏差的客户端落点

| 检视项 | 实现处理 |
|---|---|
| 照片字段所属记录错误 | `native/records.rs` 按服务端契约读取 Master 上的缩略图来源，并核对其与原图摘要的一致性；修正本地夹具 |
| Base64/hex 混用 | wire 描述仍保存 Base64，本地资源待办统一保存 hex；schema 10 保留性修正 schema 9 中旧数据 |
| failed/staged 被当成完成 | 接收晋升和诊断复用同一未完成统计；资源、发布意图和开放冲突全部纳入 applied 门槛 |
| 发布意图/准入链未接通 | 投影与发布待办同事务；只检查当前照片两角色；最终 actor 事务提交媒体、资源基线和完成事实 |
| 空 metadata 和缺失上行分类 | 协调器读取本地实际字段；稳定双资源用于新增/内容修改，照片对更新/删除保留条件；不靠空补丁清 dirty |
| 缺少独立保活/迟到回调保护 | 续租任务和轮次 watchdog 独立运行；配置/轮次/代际/操作/类别版本与单调期限在确认事务复核 |
| 多设备 operationId 冲突 | 生产操作使用持久 UUID 与固定逻辑请求；先恢复已发出结果，再派生后续操作；不把任务表当作 dirty 队列 |
| 替换后失败丢旧文件 | 发布前准备缓存并登记恢复意图；旧文件硬链接备份、短暂读写保护、回滚与首屏前恢复 |
| 多任务使用首个连接 | 资源请求始终从待办的 job 获取连接和凭证，暂存目录带 job/代际/角色，不借用第一个任务 |

## 接入实现细节

`service/coordinator.rs` 是轮次入口，`store/runtime.rs` 是同步 DbActor 命令。HTTP 或大文件准备不在数据库事务内等待。确认只清捕获版本匹配的部分，已确认事实和当前用户义务分开保存。未知响应保留原请求身份；签名能力每次从服务端描述刷新，不写入持久请求正文。

`service/transfer.rs` 先校验流式下载，再准备原图、缓存和媒体元数据；文件发布意图包含目标、同目录新文件/备份、配置与本地版本捕获。原图替换失败或最终事务拒绝时恢复旧完整版本。启动时在首屏与扫描之前执行恢复；全局关闭清理前同样先结算意图，避免把备份当作普通临时文件删除。

本地读写保护与服务端租约用途不同：前者仅保护本应用短暂的文件/缓存可见性，后者由服务器授予远端写权限。外部进程不受本地锁控制，因此恢复时仍检查路径所有权和文件变化；发现未知修改就保留备份并报告失败。

本地内容与远端元数据、或本地元数据与远端内容的独立修改按已确认基线协调；同类变更或不明确身份保留冲突。冲突解决交互、显式云删除用户入口、完整 UI 状态和系统性双设备恢复旅程仍属于 C1.5/C1.6，不因本轮代码修订而标为已验收。
