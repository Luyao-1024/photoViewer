# 原生云端同步使用与实机验证

PhotoViewer 提供 Native SyncServer 双向同步。服务端契约仍只由[服务端协议链接索引](native-sync-protocol.md)维护；本文记录客户端操作、范围和本地验证方法。

## 使用

在设置左侧选择「云端同步」，右侧直接显示总开关、同步概览、同步任务和范围说明，不再进入第二层页面。任务卡片可原地展开；无任务时提供添加引导。

启用同步后，选择「添加服务器」，输入 HTTPS 地址、用户名、密码和本地照片根目录，点击「登录并验证」。成功后选择服务器已配置的区域，勾选允许上传的物理相册，再保存。会话保存到系统密钥环，密码只用于当次登录，SQLite 仅保存凭证引用和服务器身份。空相册选择表示仅接收云端照片；不会自动上传整个根目录。新增的扫描工作在后台进行，已索引且 mtime/size 未变化的文件不重新读取正文计算摘要。

已保存任务每 15 秒检查一次；设置中的「立即同步」和照片页顶部下拉可以主动触发。暂停任务后保留配置与历史；继续后自动检查。修改相册范围先编辑后接受，取消、无效草稿及重复保存同样的范围不会停止任务。修改被接受后，旧配置停止发起后续传输，已开始的本地发布先安全结算，再应用最新配置。

任务卡片默认折叠，显示本地目录名和当前状态。展开后可查看完整本地路径、服务器、用户名和区域，选择上传相册或管理云端照片。上传范围摘要明确区分仅接收、已选相册数量和全部相册。任务的「更多」菜单集中提供暂停/继续、重新登录、退出登录和移除；移除保持二次确认。后台刷新只更新卡片内容，不重建现有卡片，因此不会丢失展开状态、菜单或键盘焦点。切换分类、展开卡片和打开菜单均不修改同步配置。

同一服务器的不同用户需选择不同且不重叠的本地根。任务中「退出登录」撤销当前会话并暂停该任务，「登录并继续」只允许重新进入原账户，不把任务切换到其他用户。详情和旧单账户升级见[多账户接入](native-sync-accounts.md)。

同一 recordId 在两端都被修改时，元数据与照片内容分别以真实修改时间较晚的一端为准，自动继续同步；时间相同使用来源与事件 ID 稳定排序。上传先后不决定胜负，路径相同本身也不代表 recordId 相同。

每张照片在自己的原图、缩略图与本地缓存就绪后入库，不等待整个相册。浏览图库使用本地文件。收藏及原图修改通过数据库中的版本和 dirty 字段同步；离线或失败保留待办。未知提交结果先通过原操作回执核实，不会把超时当作未提交。

「管理云端照片」提供显式云端删除、已删除照片的新身份重新上传，以及冲突的版本选择。云端删除保留本地照片；另一设备收到完整删除投影后保留本地文件并停止自动重传。选择「使用本地版本」前保存已校验的竞争云端资源，选择「使用云端版本」前保存本地原图和决策信息。恢复副本在应用数据目录旁的 `sync-recovery`，界面显示具体目录。隐藏照片仍需要支持该表示的客户端取消隐藏，不会公开为本地普通照片。

关闭总开关前需要确认：同步历史会清除，连接、范围及本地/云端照片保留。移除任务需要确认，会移除该任务及其凭证，也保留两端照片。下行遇到同相册、同名的本地文件时，先比较大小；同大小才计算 SHA-256。相同内容合一，不同内容把本地文件保留为第一个空闲的 `文件名_1.ext`、`文件名_2.ext`……，云端文件保持原名。普通本地照片不记录 SHA-256，本地新增或修改准备上传时才计算上传摘要。

当前仅支持原生 Sync/Bidirectional；Backup、原图懒下载、分享、上传断点续传不在当前范围内。下载中断会复用已经完成并校验的资源，未完成的单个资源重新下载。

## 聚焦验证

先构建相邻服务器，设置 `SYNC_SERVER_BIN` 指向实际二进制。GTK 用例在 Sandbox 中操作完整窗口并驱动真实控件，不访问真实相册或系统凭证。

```sh
DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus tools/with-at-spi.sh \
  xvfb-run -a -s "-screen 0 1920x1080x24" \
  env SYNC_SERVER_BIN=../syncserver/target/debug/syncserver \
  cargo test --locked --test ux_native_sync_settings --test native_sync_assets \
    --test db_migrations --test native_sync_receive -- --test-threads=1

cargo test --locked --lib -- core::sync::store::receive::tests \
  core::sync::device::tests core::sync::store::runtime::tests \
  core::sync::service::tests --test-threads=1
```

真实上传/下载、同 recordId 双端修改按事件时间自动收敛、删除传播及新身份重建由 `native_sync_assets` 的真实 actor/文件/服务器旅程覆盖。快照、墓碑与固定水位的协议用例在 `native_sync_receive`。开发阶段数据库版本始终固定为 1，不维护旧开发结构的迁移兼容。

## 显式实机连接工具

`examples/connect_native.rs` 不属于测试套件，只在明确提供 `--configure-library` 时运行。它会写入实际客户端连接、把指定相册上传到服务器，并在图库外创建第二个接收目录。执行前关闭使用同一数据库的应用并备份数据库与设置。此工具为既有 Bearer 文件诊断入口；连接 JSON 包含 `baseURL`、`apiKeyFile` 及 `zones`。`apiKeyFile` 也可提供仅用户可读的登录会话文件，旧 API key 只适用于没有用户的旧服务器模式；该文件必须只对用户可读，不放入仓库或报告。

```sh
DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus \
  cargo run --locked --example connect_native -- \
  --configure-library \
  --connection /path/to/private/connection.json \
  --album /path/to/Pictures/截图 \
  --evidence /path/outside/library/verification
```

工具核对每份原图的 SHA-256、两端再次同步无重复写入，并执行收藏更改的上传/接收及恢复。原始照片字节不改变。完成后启用已配置任务；报告与第二客户端数据保留在证据目录。会话只进入系统密钥环和进程内存；正常交互登录无需此诊断文件。

实机结果单独记录在[本次实现说明](native-sync-integration.md)，不把本地模拟、聚焦测试、远端 CI 或真实公网验证混为一项。
