# 单一当前账号与账号切换

服务端负责登录、会话和隔离协议；唯一来源为[用户认证契约](../../../syncserver/docs/contracts/authentication.md)和[服务端实施记录](../../../syncserver/docs/design/multi-user.md)。本文只记录客户端映射与交互。

## 使用与范围

PhotoViewer 同一时间只同步一个账号。设置顶部显示当前账号、服务器和「切换账号」，账号菜单提供登录与退出，覆盖该账号的全部目录；目录卡片只负责暂停／继续、上传范围、详情和移除，不重复提供账号操作。首次使用显示「登录同步账号」，连接后不再展示多服务器并列添加入口。

「切换账号」可以选择已经保存的账号，或登录其他账号。登录草稿、能力验证、失败、取消都不改变当前账号；只有接受「使用此账号」才切换。保存新的账号前仍需选择本地照片目录和明确的上传相册，空选择仍表示仅接收。

不同账号可复用同一个本地照片目录，配置、dirty、云端身份与接收进度仍各自保存；切换账号不会清除这些信息。不会自动把另一个账号的相册上传范围带过来。同一账号内部仍拒绝重叠目录或同一区域的重复映射。服务端支持多用户不表示客户端会同时同步多个用户。

## 持久选择与调度

SQLite 的既有 settings 表通过 native_sync_account 保存当前账号身份，sync_connections.enabled 只对这个账号的连接启用；数据库版本不变。旧的多个启用账号在调度／运行准入前收敛为一个确定的账号。删除当前账号的最后一个目录后不自动启用其他已保存账号。

切换先验证新会话与 pinned identity，再通过 actor 事务选择账号、禁用旧账号的 epoch。数据库运行准入门在旧账号的上传、接收及发布工作结算期间保持关闭，旧工作退出并结算其未完成的本地发布后才允许新账号开始；无法安全结算时拒绝切换并恢复原选择。直接周期、接收和下载入口都遵守同一运行准入；自动重试、照片页触发、后台刷新也只针对当前账号。重启保持选择，不依赖内存中的暂停标记。

概览、同步分母和云标记只读取当前账号；已保存但未选中的账号不会因后台请求、范围变更或刷新自动重新参与同步。

## 凭证与身份保护

密码仅用于当次认证，平台凭证服务保存会话，SQLite 仅保存引用与已验证用户身份。每次传输核对实际身份、namespace、endpoint 和数据库 generation；错误账号的有效会话同样不能推进原任务进度或覆盖照片。

重新登录只接受被选择的原账号；先验证该账号全部连接的身份，再等待该账号的旧工作结算、更新会话并继续各目录，成功后把它作为当前同步账号。退出会撤销该账号各目录的会话并暂停它们，不启用其他已保存账号。旧无用户身份关系只能显式升级至同 namespace/generation 的原数据接管者，保留媒体、dirty 和进度。

## 当前功能的聚焦验证

- native_sync_accounts：真实服务器验证账号切换、未选中账号的周期／接收／下载拒绝、错误凭证不切换、切回后保留进度。
- single_account_ 单元用例：同账号目录归组、同目录跨账号保存、选择持久化、旧 epoch 失效、移除后不隐式启动其他账号，以及旧运行收尾前禁止新运行进入。
- ux_native_sync_settings：Sandbox 中完整窗口的真实点击，覆盖当前账号、切换取消、错误密码、验证草稿、接受新账号、只显示当前账号目录和切回已有账号。
