PhotoViewer UI 命名参考

本页是该 Rust + GTK/libadwaita 相册应用的真实 UI 组件命名图谱。界面结构图上的标签默认只显示 「这块区域该怎么称呼」，把鼠标悬停到标签上才会显示其具体实现类型（控件类型 + 模板 child-id / Rust 结构体名，取自 data/ui/*.blp 与 src/ui/*.rs）。 完整的中文名 ↔ 标识符对照见下方「图例」表；先看「可拖动 / 可缩放」醒目提示框。

可拖动 / 可缩放元素 — Draggable & Resizable Elements

这是整份参考的核心。“看起来像分隔条就能拖”是错的。 下表列出每个可拖动 / 可缩放元素及其在代码中的真实行为。务必用这里的规范名沟通，避免再说“那个侧栏”。

规范标识符 中文 / 位置 能否拖动/缩放 真实行为（取自代码）
Adw.OverlaySplitView split_view
window.blp · 主窗口侧栏分隔		 主分隔条 / 侧栏与内容之间 不可缩放 (FIXED) min-sidebar-width: 240 且 max-sidebar-width: 240 —— min==max，拖动分隔条什么都不会发生。 侧栏宽度恒为 240px，仅在窄窗折叠为浮层时整体显隐。不要把它当成可调宽度的分隔条。
Gtk.ListBox album_list 的行
window.rs · attach_album_dnd()		 侧栏相册行（相册顺序） 可拖动重排 通过 Gtk.DragSource（载荷 = folder_path，MOVE）+ Gtk.DropTarget（attach_album_dnd）实现 仅落点提交的拖拽排序： 拖动时被拖行变暗 (.glass-sidebar-row-dragging)，DropTarget::motion 只切换上方/下方插入指示 (.glass-sidebar-row-drop-above/below)——拖动过程中不实时重排；仅 drop 时调用 reorder_album，经 albums::set_album_order 写入 DB 并 rebuild_album_rows 重建。 普通点击不会触发拖动（需越过拖动阈值）。
Adw.OverlaySplitView editor_split_view
viewer-page.blp · 查看器右侧编辑面板		 编辑面板分隔（查看器右侧） 可缩放 340–420 sidebar-position: end（面板在右），min-sidebar-width: 340 / max-sidebar-width: 420。 这是查看器里真正可拖动调宽的分隔条。内嵌 $EditorPanel editor_panel。
Adw.OverlaySplitView details_split_view
viewer-page.blp · 查看器右侧详情面板		 详情面板分隔（查看器右侧） 不可缩放 (pinned/overlay) collapsed: true + pin-sidebar: true —— 详情面板 details_panel 以浮层形式叠加在图片之上（不挤压舞台），无分隔条，宽度由 width-request 固定，仅靠 show-sidebar 滑入滑出。
Gtk.Scale brightness/contrast/saturation_scale
editor-panel.blp		 编辑面板里的滑块 可拖动（滑块） 调节亮度/对比度/饱和度；reset_btn 仅在有未保存编辑时可点。
Gtk.DrawingArea crop_overlay
viewer-page.blp		 图片上的裁剪选区 可拖动/缩放（选区） 裁剪矩形直接画在图片上，crop_ratio_box 选择比例。

一句话记忆：侧栏那条 240 分隔线是死的；相册行能拖拽排序（仅落点提交，拖动中只显示插入指示）；查看器编辑面板那条 340–420 是唯一可调宽的分隔条；详情面板是浮层不可调宽。

06 窄窗口折叠态 — Collapsed (Overlay Sidebar)
