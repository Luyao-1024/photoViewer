# WebDAV 与可扩展同步架构方案

日期：2026-09-19。状态：首版已实现，真实服务兼容性待联调。

实现前的详细行为契约见 [双向同步：关键架构、流程与约束](designs/sync-architecture-and-flows.md)，包括架构图、数据提交边界、关键流程、恢复状态机和首版验收。本文保留接入总体方案；具体流程以该详细设计为准。

本文基于当前仓库的存储、查看器、编辑器、相册、回收站实现。用户已明确选择：双向同步优先，本地和云端修改相互同步。因此采用本地图库优先的同步架构，WebDAV 是第一个同步传输适配器。首版必须覆盖双方新增、修改、冲突处理和中断恢复。远程浏览与按需原图缓存是后续可选功能，不是同步的前置条件。

当前实现位于 `src/core/sync/`：Provider-neutral 模型与 Planner、WebDAV 适配器、本地安全发布、SQLite/DbActor 状态、周期调度和恢复核对均已接线。设置页支持创建双向任务、暂停/恢复、立即同步，以及“使用本地”“使用云端”“保留双方”三种冲突处理。密码存入系统 Secret Service；Flatpak 已声明网络与 Secret Service 权限。

已由 fake provider 和本地 Mock DAV 覆盖双方新增、单侧修改、双方修改、三种冲突解决、上传响应/提交中断恢复、条件请求、中文路径及常见 HTTP 错误。阿里云主机上的 rclone WebDAV 1.60.1-DEV 已完成真实验收：该服务忽略 `If-Match`/`If-None-Match`，适配器通过 DAV Class 2 独占 `LOCK`、锁内版本核对及 `UNLOCK` 提供原子写保护；同时兼容其同一响应包含 200 与 404 多个 `propstat` 的目录 XML。尚未具备或尚未验证的范围：删除传播、单向模式 UI、远端增量 token/分页、断点续传、私人 CA、后台常驻服务、Nextcloud 联调，以及面向大图库的增量哈希优化。这些限制不得在产品文案中表述为已支持。

## 1. 目标与边界

- 同步用户选定的本地照片/视频目录与 WebDAV 目录，支持多个连接和目录映射。
- 保持本地图库离线可用，网络故障不阻塞 GTK 主线程或本地扫描。
- 首版默认双向同步，创建任务时清晰展示双方目录及方向。引擎预留仅上传备份和仅下载策略，其 UI 和产品交付可后置，不作为双向同步首版的依赖。
- 后续可接入 S3、SFTP、其他网盘 API；不假设它们都有目录、原子移动、回收站或可靠版本号。
- 第一阶段使用进程内 Rust 模块和 trait；暂不引入动态插件 ABI、独立服务或多 crate 重组。
- 首期同步原始文件、保存后的编辑结果及相对目录结构。本地图库仍只展示已完整落地并入库的媒体，远端尚未下载的条目只存在于同步清单。
- 文件同步与应用元数据同步分开交付。收藏、相册封面、排序、编辑历史不会因为原图上传而自动同步；后续增加独立元数据编解码和合并模块。
- 首期同步运行于应用进程；关闭应用后暂停，重启自动恢复。需要关窗后持续同步时，再设计后台服务的生命周期。

## 2. 当前实现与接入影响

| 当前边界 | 现状 | 接入要求 |
|---|---|---|
| `core/backend/mod.rs` | 导出本地扫描模块，没有通用后端 trait | 新增协议适配边界；保留本地扫描的现有优化 |
| `core/media.rs`、`schema.sql` | 媒体必须有本地 `path` / `folder_path`，URI 唯一 | 保留本地模型，另建同步对象身份和双方位置映射 |

| `ui/viewer/stage.rs` | 图片、视频、动态照片都读取本地文件 | 复用；下载完成并发布后才进入现有查看链路 |

| `core/db.rs::reset_library_database` | 清空媒体与相册数据 | 清理流程不得丢失待上传内容、同步基线、删除记录和冲突 |
| Flatpak manifest | 无 `--share=network`，构建离线 | 新增网络权限、凭据访问方案和依赖打包验证 |

## 3. 模块划分

```text
src/core/
  sync/
    model.rs           连接、目录映射、对象身份、基线、冲突、删除记录
    provider.rs        SyncProvider 接口、能力与错误类型
    providers/
      webdav/          HTTP、DAV XML、认证、路径与能力探测
    registry.rs        按 provider kind 创建适配器
    local.rs           本地快照、变更发现、安全发布与扫描集成
    discovery.rs       远端遍历/增量发现与快照完整性
    planner.rs         根据双方状态和上次基线生成操作计划
    executor.rs        执行上传、下载和条件变更
    scheduler.rs       并发、优先级、退避、取消、恢复
    staging.rs         持久上传快照、下载临时文件、恢复日志
    store.rs           同步状态查询及 DbActor 命令边界
    service.rs         UI 使用的任务与连接服务
src/platform/
  credentials.rs       系统凭据存储适配
src/ui/
  ...                  连接设置、同步任务、进度、冲突处理
```

依赖方向：UI → SyncService → Planner / Scheduler / Executor → SyncProvider。WebDAV 实现 SyncProvider；Executor 通过 LocalReplica（`local.rs`）处理本地文件，通过 Store 提交状态。协议适配器不直接写数据库，也不生成 GTK 对象。数据库提交统一经过 DbActor。

连接配置和同步任务分开：一个连接描述账号、端点及凭据引用；一个任务描述本地/远端目录映射、方向、筛选和删除策略。同一个连接可以承载多个任务。首期拒绝同一应用内重叠的映射根，避免两个任务同时写同一个本地或远端目录；多设备并发由版本条件和冲突机制处理。

## 4. Provider 契约

第一版采用 `async-trait` 与 `Arc<dyn SyncProvider + Send + Sync>`，复用当前 Tokio runtime。

| 接口 | 语义 |
|---|---|
| `capabilities()` | 返回读取、写入、条件写入、范围读取、移动、增量枚举、回收站等能力；默认不支持 |
| `ensure_collection(key)` | 创建必要父目录；WebDAV 对应 MKCOL，对象存储可为逻辑前缀；不支持单独空目录时明确声明 |
| `list_children(parent, cursor)` | 有界批次/流式枚举，明确本次目录枚举是否完整；游标可为空，不承诺服务器支持分页 |
| `stat(key)` | 返回对象位置、尺寸、修改时间及可用的版本验证器 |
| `read(key, expected_revision, range)` | 流式读取，报告实际版本；强校验不可用时显式标记弱保证 |
| `write(key, condition, body)` | 流式写入；区分仅新建、基于版本替换，返回新版本 |
| `move/delete(key, condition)` | 显式变更；能力不足返回 Unsupported，不假装具备原子性 |
| `changes(cursor)` | 可选增量枚举；没有能力时使用目录遍历 |

`ObjectKey` 是适配器管理的对象定位符，不是 OS `PathBuf`。`Revision` 是带验证强度的、不透明的内容版本；WebDAV ETag 不是文件哈希，更不是稳定文件 ID。

错误分类至少包含：认证失效、无权限、离线/超时、限流、空间不足、对象不存在、版本冲突、不支持、协议响应异常。调度器按分类决定重试或等待用户处理。

能力必须结合端点探测、实际响应及当前权限判断。`OPTIONS` 声明不能独自证明条件写入或原子替换可靠。新增 provider 时提供适配器、能力声明、注册和契约测试；服务特有的登录及配置 UI 可以单独扩展。

## 5. 身份、数据库与迁移

保留本地 `MediaId` 作为 UI 和查询主键。同步对象有独立持久 ID，不依赖可重建的媒体索引行；其 `media_id` 关联允许为空。首期远端使用普通目录和原文件，相对路径负责配对、双方指纹和共同基线负责判断变化。本地同步 ID 不会自动成为跨设备身份；未来应用元数据同步需要额外的版本化 manifest/sidecar 交换身份。

建议按阶段加入以下表，而非第一阶段一次建完：

| 表 | 用途 |
|---|---|
| `sync_connections` | provider 类型、端点、非敏感配置、凭据引用 |
| `sync_jobs` | 方向、目录映射、运行策略、删除策略 |
| `sync_entries` | 持久对象 ID、可空媒体关联、相对路径、双方当前版本/指纹、共同基线、删除记录；任务内位置唯一 |
| `sync_tasks` | 操作 ID、依赖、预期版本、产物引用、状态、重试时间 |
| `sync_conflicts` | 基线与双方版本、冲突原因、用户处理结果 |

首期不修改 `media_items.path` / `folder_path` 的非空约束，不引入远程图库的副本表、ContentResolver 或集合身份迁移。远端枚举结果进入同步清单；文件完整下载并安全发布到本地目录后，再复用元数据提取、媒体入库与相册刷新。

本地现有 MediaId、收藏、相册封面和排序保持原有语义。同步下载目录需纳入受管理的扫描根；若用户排除该目录，暂停对应同步任务并提示处理，不能推断为用户删除全部照片。

分版本事务迁移新增同步表，为待执行任务、任务内相对路径和重试时间建索引。远端 hash 未知时记录为未知，必要时下载校验，不用空字符串或 ETag 冒充内容哈希。

同步到本地的文件是用户图库原件，不属于可淘汰缓存。上传使用不可变快照，避免传输过程中源文件被编辑；持久 staging 区记录快照所属任务及配额。磁盘空间不足时暂停任务，不降级为读取不稳定源文件。下载临时文件、待上传快照及冲突副本不能被普通缓存清理删除。

媒体索引重建必须保留同步对象 ID、任务、基线和删除记录。同步条目不对媒体行使用级联删除，可通过 `ON DELETE SET NULL` 清除临时关联，重建后按本地位置和指纹重新关联。实现阶段需要改造当前整库清空操作，有未完成操作时先暂停调度，再执行保留同步状态的重建流程。

## 6. 同步工作流

1. 添加连接，测试认证、选定根目录和所需能力；选择本地目录、远端目录及同步方向。
2. 首次扫描双方，建立清单并生成预览：新增、待上传、待下载、同名待核对和预计传输量。首次缺失不等于删除，因为尚无共同基线。
3. 持久化任务计划；执行期间限制并发、带宽和 staging 使用量，支持暂停与取消。
4. 上传：等待本地写入稳定，创建并校验不可变快照，按预期远端版本写入，核对结果后提交基线。如果快照后源文件又变化，另建下一次任务。
5. 下载：写临时文件并验证长度、版本与内容指纹；同文件系统内准备发布文件，先持久化恢复日志，再复查本地基线并保留被替换版本，原子发布后提交数据库结果并标记日志完成。
6. 发布完成后复用本地元数据提取、缩略图失效和领域事件；同步引擎记录操作来源，watcher 做幂等对账。
7. 应用运行时由本地 watcher、周期远端扫描、手动“立即同步”和网络恢复触发对账；重启核对未完成任务并继续。

本地扫描和网络扫描都必须报告完成范围。断网、根目录不可达、权限错误、枚举取消或过滤规则变化不能生成删除传播任务。同步移除连接或移除任务只解除关联，不删除双方文件。

下载发布与编辑保存、重命名、移动、删除使用共享的本地变更协调锁，避免应用内部竞争。外部程序不受该锁约束，仍需要最终复查及可恢复替换；不能声称一次 stat 就能完全消除竞态。下载临时文件、发布用隐藏文件和 `.bak` 不参与照片同步。

远端目录名映射到本地时检查路径边界、符号链接逃逸、大小写和 Unicode 名称冲突；不静默覆盖映射冲突。首期不跟随同步根内指向根外的符号链接。空目录是否同步取决于 provider 能力，文件的相对目录结构必须保留。

后续若需要仅云端浏览，再引入 ContentResolver、可空本地位置及离线缓存；当前同步引擎的传输与 provider 可被该功能复用。

## 7. WebDAV 协议实现

- 建议 `reqwest` 配合流式响应、超时与 TLS 校验，`quick-xml` 解析 DAV XML，`url` 处理 URI；落地时确认依赖版本、Tokio features 和 Flatpak 离线依赖包。
- 使用 `PROPFIND Depth: 1` 按目录递归，避免依赖 `Depth: infinity`。处理 XML namespace、目录自身条目、每个 `propstat` 状态和混合成功的 207 响应。
- 不假设标准 DAV 支持分页：大目录流式解析、批量入库，设置响应预算。被截断、取消、部分失败的枚举不能触发缺失删除判断。
- `getetag`、`getlastmodified`、`getcontentlength` 作为变化信号；支持时使用 `sync-collection` / sync-token。增量 token 与对应变更在同一事务提交，token 失效回退完整遍历。
- 远端修改时间加大小只是弱变化信号，不能证明内容相同。弱 ETag 不能用于 `If-Match` 强比较；缺少可靠条件更新的服务器默认只读或仅新增备份，禁用自动覆盖。
- 新建对象使用 `If-None-Match: *`；替换使用强 ETag 条件请求，412 进入冲突。临时上传再 MOVE 仅用于已验证满足目标前置条件的服务，不能假设所有 DAV 服务器都能原子条件替换。
- 续传仅在 Range 及版本验证满足要求时启用；检查 206、Content-Range 和版本。服务器返回 200 或文件已变更时丢弃断点重新下载，不能拼接两个版本。
- `href` 可以是绝对或相对 URI；规范解析后验证来源和选定根目录边界。防止路径穿越、重复解码和不同 URL 编码引起的身份碰撞；覆盖中文、空格、`%`、`#`、`?`。
- 密码和 token 交给系统凭据存储，通过 `CredentialStore` 抽象隔离；不可用时提供仅会话保存。配置、数据库、日志不得包含明文密码或认证头。
- 默认 HTTPS 并校验证书；私人 CA 提供明确配置路径。重定向不得跨来源转发认证信息。
- Flatpak 和开发启动脚本都需要网络权限；系统凭据服务的最小权限与可用性需要在实际沙箱验证。更新 Cargo lockfile 及离线构建依赖清单。

## 8. 同步调度与冲突

同步流程：发现变化 → 比较双方与上次成功基线 → 持久化计划 → 网络/文件操作 → 提交结果与新基线 → 发布领域事件。

Planner 是可独立测试的纯逻辑。不能采用“时间戳较新者覆盖”，因为设备时间和服务器时间不保证一致。

| 相对共同基线的变化 | 双向模式默认处理 |
|---|---|
| 仅本地修改 | 基于远端预期版本上传 |
| 仅远端修改 | 下载新版本，发布前复查本地未变更 |
| 双方内容相同 | 更新共同基线，不重复传输 |
| 双方修改且内容不同 | 保留双方，建立冲突 |
| 一方删除，另一方未变更 | 仅在该任务明确启用删除传播时处理 |
| 一方删除，另一方修改 | 冲突，不自动删除 |
| 首次关联时双方同名 | 校验内容或要求选择，不直接认定为同一版本 |

备份模式默认仅新增；源文件删除不删除备份，修改内容优先写版本副本。仅下载模式不反向上传本地编辑，遇到双方修改也进入冲突。双向删除单独开启，并使用可恢复策略；WebDAV 标准没有统一回收站。

删除记录独立于媒体索引保留，不因从本地数据库移除条目而消失。只有先前存在共同基线、相关目录完整扫描且明确启用删除传播时，才计划删除。删除传播关闭时，有基线的单侧缺失进入待处理状态，不自动补回。单机删除记录不能保证全新客户端不重新上传旧文件；跨设备全局删除收敛需要后续共享删除日志与设备确认协议，首版不作此承诺。

没有稳定服务端对象 ID 的外部重命名可能只能识别为新增加消失。仅在有可靠证据时保留关联，不能承诺所有 WebDAV 服务都能无损识别外部重命名。

应用内明确重命名可保留同步关联；默认删除关闭时，旧远端位置保留为待处理差异，不能声称已完成两端名称镜像。条件移动和删除传播按后续能力与策略单独开放。

任务状态：`queued → running → succeeded`，旁路包括 `retry_wait`、`blocked_auth`、`conflict`、`cancelled`。重启后重新核对遗留 running 任务再决定重试。

远端写入与 SQLite 提交无法构成同一事务：每次远端副作用前先持久化操作 ID、预期版本和产物指纹。超时不能等同于未成功，重试前先核对目标；无法判定时进入待处理状态，不能重复盲目覆盖。目标是可恢复的至少一次执行，不宣称 exactly-once。

用户编辑所形成的本地变更和 outbox 任务在同一个 DbActor 事务中提交；外部本地文件修改由 watcher 发现，启动扫描补偿遗漏。文件系统发布与 DB 提交之间的崩溃通过 staging 日志恢复。下载应用到本地前复查基线，防止覆盖传输期间的新编辑。

本地 watcher 仍负责本地文件；下载缓存、临时文件及 staging 不进入普通扫描根。对于真正同步到用户目录的变更，以版本/操作记录对账，避免 watcher 把远端下载当作新上传形成循环。

调度按账号和全局限制并发，同一对象的变更串行；优先用户手动任务及冲突处理，再到后台对账，并为本地浏览和编辑保留 I/O 资源。重试使用指数退避、抖动和 Retry-After；认证、权限和配额错误暂停对应任务。网络 I/O 不占用 DB actor，任务进度通过可合并状态通道传递，不能逐字节塞满现有无损领域事件通道。

## 9. UI 与现有功能策略

- 设置增加“连接与同步”：连接列表、连接测试、目录映射、方向、自动同步、删除传播、最近成功时间、立即同步及暂停/重试。
- 同步状态展示扫描中、待上传、待下载、传输中、已同步、冲突、失败；按任务汇总文件数、字节数和错误，不把上传排队误报为云端已保存。
- 当前本地网格、查看器和编辑器继续工作。编辑保存后显示本地已保存与待同步两个不同状态，失败不回滚用户的本地编辑。
- 冲突界面提供保留双方、使用本地、使用远端；执行用户选择前再次检查双方版本，不能覆盖处理冲突期间的新修改。
- 清除缓存、排除扫描目录、解除同步和删除文件是独立操作。删除传播开启后，本地删除/相册批量删除应明确提示将影响远端；批量异常删除进入待确认状态。
- 本地回收站保留现有语义。远端回收能力作为可选扩展；不把 WebDAV DELETE 表现成“可从系统回收站恢复”。
- 收藏等元数据第一阶段仍为本地状态；未来跨设备同步采用带版本的 sidecar/变更记录，并定义字段级冲突规则。绝不直接同步 SQLite/WAL 文件。
- UI 实现时更新 Blueprint、模块说明和视觉命名映射，保留现有 Liquid Glass 和导航宽度约束。

## 10. 交付阶段与验收

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| A：同步核心 | Provider 契约、LocalReplica、同步表、纯 Planner、持久任务、fake provider | 双向变化与冲突规则可验证，单向策略可扩展；本地图库数据模型保持兼容 |
| B：WebDAV 首个闭环 | 连接/目录映射、扫描、上传/下载新增文件、暂存恢复、进度 UI | 双方新增可同步，已有同名文件核对或报冲突；不自动覆盖或传播删除；重启可恢复 |
| C：完整内容同步 | 共同基线、条件更新、编辑/重命名集成、冲突处理、自动调度 | 单方修改可靠传播，双方修改保留数据；不可靠条件写入端点明确限制功能 |
| D：删除与产品完善 | 删除记录、可恢复删除、批量删除保护、清理/重建集成、真实服务矩阵 | 离线与部分扫描不误删，索引重建不丢状态，删除传播需单独启用 |
| E：扩展验证 | 第二种真实 provider、可选应用元数据同步 | 新服务复用 planner、暂存恢复和调度；新增代码集中于适配及认证配置 |

A–C 是双向同步首版的内部实施步骤；B 仅作为内部验证里程碑，不能作为首版交付终点。首版验收必须包含本地新增/修改上传、远端新增/修改下载、同时修改进入冲突，以及断网和重启后正确恢复。D 中清理/索引重建保留同步状态的保护必须随首版完成；可选删除传播及其 UI 在后续开放。远程图库浏览、单向模式 UI 和第二种 provider 不进入首版关键路径。

重点测试：

1. Provider 共享契约测试及 fake provider：分页/批次、版本条件、取消、重试、能力不足。
2. Mock DAV HTTP：207 部分失败、中文编码、弱/缺失 ETag、401/403/412/429/507、Range 失效、连接中断、跨来源重定向。
3. Planner 表驱动测试：首次同步、双方修改、删除与修改、重命名不确定、弱版本信号。
4. 崩溃注入：上传完成未提交数据库、下载未发布、DB 提交失败、运行中退出、编辑与下载发布竞争、磁盘满。
5. 迁移与回归：旧 MediaId/收藏/相册保持；同步任务查询索引；索引重建保留基线；本地 watcher 不形成同步循环。
6. GTK 流程：连接测试、映射和方向设置、同步暂停/恢复、编辑后待同步状态、缓存清理、冲突处理和批量删除提示。
7. 真实服务矩阵：至少一种普通 DAV、一种 Nextcloud，以及用户实际 NAS/网盘；同时验证 Flatpak 网络、证书与凭据访问。Mock 测试通过不能代表实际服务兼容。
8. 每次实现变更按 AGENTS.md 和当前 CI 工作流运行完整格式、clippy、GTK/AT-SPI 测试；Mock 测试结果不能替代真实 WebDAV 与 Flatpak 联调。

## 11. 实施前待确认的产品选择

- 已确定首版优先交付双向同步，默认本地和云端的新增、修改相互传播；仅上传和仅下载作为后续可选策略。
- 阿里云主机中的 rclone WebDAV 已通过隔离临时目录和一次性账户完成协议与双向同步联调；端点、账号和测试凭据不进入仓库。其他服务仍需按同一验收项单独验证。
- 同步目录、是否包含视频、触发周期、带宽与暂存空间预算。
- 后续是否需要跨设备同步收藏/相册，以及双向删除策略。

这些选择影响默认策略与验收，不改变 SyncProvider、LocalReplica 与 SyncEngine 分离的总体设计。
